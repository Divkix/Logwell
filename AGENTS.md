# Repository Guidelines

## Project Overview

Self-hosted, single-tenant logging + incident-intelligence platform. Services ship logs via OTLP/HTTP JSON (`POST /v1/logs`) or simple JSON (`POST /v1/ingest`) with per-project API key (`Bearer lw_…`); logs store in PostgreSQL with full-text search, error/fatal logs auto-group into fingerprinted incidents, live dashboard streams via SSE.

## Architecture & Data Flow

- **Request lifecycle** (`src/hooks.server.ts`): `handle` wraps `app` in `withSecurityHeaders` (`utils/security-headers.ts`: nosniff, `X-Frame-Options DENY`, `Referrer-Policy same-origin`, HSTS only with an https `ORIGIN`) so early 429/403 returns get them too → build guard → `initAuth()` + cleanup scheduler → `locals.db` injection → login rate-limit (per network, then per account) → signup kill-switch (403) → `/v1/*`, `/api/health` skip session → session resolve + better-auth handler + CSRF. Nonce CSP is Kit's `csp` in `vite.config.ts` (`style-src` keeps `unsafe-inline`); a new external script/font/image host needs a directive there. `app.html` holds the pre-paint theme script (mirrors mode-watcher; `theme-init.component.test.ts` guards drift); `hooks.client.ts` sets zod jitless. `uncaughtExceptionMonitor` logs `[FATAL] <errorId> | <origin> | <message>` and leaves Node's crash intact.
- **Two API families — do not conflate:**
  - `/api/**`: session cookie + project ownership, CSRF on non-GET/HEAD/OPTIONS. Dashboard backend.
  - `/v1/**`: API-key auth, pre-auth per-IP limit (`RATE_LIMIT_INGEST_IP_RPM`) + per-project limit (`INGEST_RPM=600/min`), 429 + `Retry-After: 60`, CSRF-exempt.
- **Ingest pipeline** (`src/lib/server/utils/ingest.ts:ingestLogs`): Content-Type guard → key validation (SHA-256 → `{projectId, keyHash}`, cached; re-verify `(id, apiKeyHash, isActiveProject)` against the row every request, because the cache lags rotation/delete) → rate-limit → parse/normalize → fingerprint + incident upsert in one tx → `insert` with `incidentId` → SSE broadcast. `/v1` routes are thin adapters (`parseOtlpIngestBody` / `parseSimpleIngestBody`).
- **Incidents:** error/fatal only; fingerprint = `SHA-256(service|sourceFile|lineNumber|normalizedMessage)[:32]`, normalize = lowercase/trim, mask UUIDs/hex/IPs/numbers, collapse whitespace (order load-bearing). Upsert on `(projectId, fingerprint)` bumps `lastSeen`/`totalEvents`/`highestLevel` (`LEVEL_RANK`: debug 10 … fatal 50). Status is time-derived (`getIncidentStatus(lastSeen)` vs `INCIDENT_AUTO_RESOLVE_MINUTES`), never stored. Detail analysis (`utils/incident-analysis.ts`) covers the newest 10,000 events (`analyzedEvents`). Retention also prunes incidents past the cutoff that own no logs.
- **SSE bus** (`src/lib/server/events.ts`): in-process singleton, project-scoped listeners. `POST …/logs/stream`, `POST …/incidents/stream` (POST for CSRF). Batched `event: logs/incidents` + heartbeats; slow consumers drop batch, keep connection. Heartbeat (`SSE_HEARTBEAT_INTERVAL_MS`, default 30s) only has to beat reverse-proxy read timeouts — Node never times out a response still being written. Open streams hold shutdown until `SHUTDOWN_TIMEOUT` (image: 8s) force-closes them. Process-wide cap `SSE_MAX_CONNECTIONS` (200) → 429 `too_many_streams` + `Retry-After: 60`; `useLiveStream` waits Retry-After without spending `maxReconnectAttempts`. Single-process — no cross-replica fan-out (same for rate limiter and stream cap).
- **Auth:** better-auth `username()` plugin, 7d sessions, rate limiter enabled by `isProduction()` and keyed by the app-set `x-logwell-client-ip` header (`advanced.ipAddress.ipAddressHeaders`; client values overwritten). Login limits: per network (`RATE_LIMIT_LOGIN_RPM`, IPv6 by /64) and per account (`RATE_LIMIT_LOGIN_ACCOUNT_RPM`, `utils/login-account.ts` resolves email/username to the user id; unreadable bodies share an `unattributed` bucket; tokens refunded unless better-auth answers 401; an exhausted account bucket still admits networks that account signed in from in the last 30 days — `KnownLoginNetworks`, in memory, recorded on 2xx only). `loginAccountKey` mirrors better-call/better-auth body parsing — `login-account.integration.test.ts` flags drift on upgrade. lazy `createAuth(db)` proxy (throws before `initAuth()`). Prod code MUST use `auth.api.getSession()`; `src/lib/server/session.ts` is test-only (unsigned cookie, forgeable).

## Development Commands

Always `pnpm run …` (`pnpm-lock.yaml`, `packageManager pnpm@12.14.0`). Node.js is the runtime: `node build/index.js` serves the app, `tsx` executes `scripts/*.ts`. Ports: dev **5173**, preview **4173**, prod **3000**.

```bash
pnpm run dev / build / preview        # vp dev/build (@sveltejs/adapter-node → build/index.js, prod :3000)
pnpm run lint                         # vp check (= format+lint+typecheck); --fix to fix
pnpm run check                        # svelte-kit sync + svelte-check --tsgo
pnpm run knip                         # dead code — run pre-commit with vp check
pnpm run test:unit / :component / :integration  # vp test run --project <tier>
pnpm run test:coverage                # v8, signal-only (no gate)
pnpm run test:e2e                     # Playwright; needs real Postgres + seeded admin
pnpm run db:start / db:stop           # docker compose up -d / down -v (postgres:18-alpine)
pnpm run db:generate / db:migrate     # after schema edit commit SQL; migrate in prod/CI, never push
                                      # db:migrate = tsx --env-file-if-exists=.env scripts/migrate.ts: drizzle migrator under
                                      # pg_advisory_lock 0x4c574d47 (no timeout), real env wins over .env; drizzle-kit migrate takes no lock
pnpm run db:push                      # dev/ephemeral only
pnpm run db:seed / incidents:backfill # seed needs ADMIN_PASSWORD (≥8 chars); scripts run under tsx
pnpm run sdk:test / sdk:build / sdk:lint  # delegates to sdks/typescript
```

Local build needs dummy env: `DATABASE_URL=postgres://… BETTER_AUTH_SECRET=<≥32 chars> pnpm run build`.

## Code Conventions & Common Patterns

- **DB seam:** handlers never import DB directly. Use `getDbClient(event.locals)` (`src/lib/server/db/db.ts`); tests overwrite `locals.db` with PGlite. `DatabaseClient = PostgresJsDatabase | PgliteDatabase`; `.returning()` lists columns explicitly minus `search`, with deliberate `as any`.
- **Ownership guards** (`owned-project.ts`): `requireAuth` → 401 `/api/*`, 303 pages. `requireOwnedProjectRoute` (JSON 404 `Response`, check `instanceof Response`) vs `requireOwnedProjectPage` (`error(404)`). Ownership miss = **404 not 403**. CSRF runs before ownership on mutating routes.
- **Soft delete:** DELETE sets `deletedAt` and revokes the key (`apiKeyHash = 'deleted:<id>'`, never valid hex); name reusable via partial `uq_project_name_owner WHERE deleted_at IS NULL`. `jobs/project-purge.ts` deletes logs/incidents in paced batches, row last (scheduler: purge, then retention); overlapping runs are safe — a short log batch with logs left skips the project, and the row delete requires no logs/incidents left (never a big cascade). Every project lookup filters `isActiveProject` (`db/predicates.ts`, no app imports) — guards, lists, `validateApiKey`, ingest re-verify, regenerate (404 if its UPDATE matches no active row). Invalidate the key cache **after** the UPDATE commits (regenerate, DELETE). Scripts can't import `owned-project.ts` (loads env) — import `db/predicates.ts` or use `incident-backfill.ts:listBackfillProjects`.
- **CSRF:** `/api` non-GET without `Origin`/`Referer` → 403. Kit 3 also rejects bodiless/form mutations whose Origin ≠ its `https://<Host>` guess before hooks run — client fetches without a body send `Content-Type: application/json`. Test `Request`s must set same-origin `Origin`. `/v1` exempt.
- **Ingest contract:** `/v1/ingest` per-log failures ≠ request failure → **200** `{accepted, rejected, errors[]}`. Only batch-level → 4xx (`unauthorized`, `rate_limited`, `invalid_json`, `batch_too_large` at 100, `validation_error` — incl. JSON nested >256). Both 429s carry `Retry-After: 60`. Per-record limits (`ingest-limits.ts`): message/OTLP string body >98,304 chars truncated with `… [truncated, N characters]` (fingerprint masks the digits); structured JSON >65,536 chars rejected per record; timestamps beyond now + `INGEST_MAX_FUTURE_SKEW_MS` (5 min) or before 0001-01-01 (PG rejects `toISOString()`'s expanded years) → receive time (`clampLogTimestamp`; OTLP keeps raw `timeUnixNano` in attributes). Non-message strings/keys: NUL stripped, lone surrogates → U+FFFD (PG json rejects `\ud800`).
- **Query:** cursor-preferred keyset `(timestamp DESC, id DESC)`, base64url opaque; malformed or micros outside the Postgres range → 400 `invalid_cursor`. `limit` 1–500 (default 100), `limit+1` for `has_more`. `offset` deprecated, capped at 10,000 → 400 `offset_too_large` (page: `error(400)`); the logs page drops an invalid cursor to page one with offset 0. `total` via bounded `cappedLogCount` first page only. Filters: `level` CSV (`parseLevelFilter`; 2+ levels → one LIMITed page per level on `idx_log_project_level_timestamp_id`, merged by `UNION ALL`, since `level = ANY` can't use it in keyset order; offset path stays a single query), `from`/`to` ISO, `search` (max 256 → 400 `invalid_search`; the page cuts to 256) → `to_tsquery('english',…)` on `search` tsvector/GIN.
- **Bounded aggregates:** project list/detail counts cap at 10,000 (`logCountCapped`, `totalLogsCapped`; capped `levelCounts` = newest 10,000) — read as "10,000+". `/stats`: default 24h, max 7d (`time-window.ts`), 400 `invalid_range`/`invalid_date`, echoes effective `from`/`to`; `/stats/timeseries` scans at most one range of buckets from `from`, capped at now. The window bounds time, not rows.
- **Schema sync:** `search` STORED generated column uses `||` + `COALESCE`, not `concat_ws` (STABLE, illegal in STORED). Keep in sync: `schema.ts` + recreating migration `drizzle/0010_*.sql` (the PGlite tier generates its DDL from `schema.ts` via drizzle's dialect). `tests/integration/db/migrations.integration.test.ts` applies `drizzle/*.sql` to PGlite and asserts its indexes match the reflected schema (incl. partial-index `WHERE`), so index drift fails CI. `0013_log_index_rework` is hand-edited (`IF [NOT] EXISTS`, aborts with a HINT over an INVALID pre-built index; relies on PG18 skip scan); `0014_project_soft_delete`.
- **Svelte 5:** never make hooks' `_isConnected`/`_isConnecting` `$state` — `$effect` read+write self-triggers `effect_update_depth_exceeded`. UI gets connection only via `onConnectionChange`. Live list capped client-side (`MAX_STREAMED_LOGS=10000`).
- **Naming:** `requireOwnedProject*`, `parse*IngestBody`, `*Error` (`InvalidCursorError`), `*.unit.test.ts` colocated / `*.integration.test.ts` / `*.component.test.ts`. `// oxlint-disable-next-line <rule>` for inline suppress.
- **Errors:** server logs full context, client gets sanitized message + error ID (`error-handler.ts`). Postgres cancellation (SQLSTATE 57014, from `DB_STATEMENT_TIMEOUT_MS`) → 503 `{error:'query_timeout', message, id}`.

## Runtime/Tooling Preferences

- **pnpm 12 + Node.js.** pnpm manages dependencies (`packageManager pnpm@12.14.0`; the app and `sdks/typescript` share the root `pnpm-lock.yaml`). Settings live in `pnpm-workspace.yaml`, not `.npmrc`, and install scripts are denied unless listed under `allowBuilds` — an unreviewed one fails `pnpm install`, as does a `package.json` change (`pnpm install` is frozen by default; regenerate with `pnpm install --lockfile-only` first). Node.js (`engines.node`, Node 24 LTS in CI `runtime: node@24` + Docker `node:24.22.0-alpine`) is the runtime: it serves the built output, and `tsx` (a prod dependency — the image's entrypoint seeds with it) runs `scripts/*.ts`, which use extensionless TS imports Node's native type stripping can't resolve. SvelteKit 3 + adapter-node 6: Kit config lives in `sveltekit({...})` in `vite.config.ts` (no `svelte.config.js`), `#lib/*` is a package.json `imports` map (explicit `.js`/`.svelte` extensions), tsconfig extends `$app/tsconfig`. `tw-animate-css` stays in `ssr.noExternal` (style-only export). One-off CLIs: `pnpm dlx → bunx → npx`.
- **Vite+ (`vp`) 1.3.0**, **Vitest 5.0.5** via the workspace catalog/overrides; `@vitest/coverage-v8` must match the runner (hard-fail otherwise). Root TS 6 + `@typescript/native` 7 for `--tsgo` (svelte-check 4.x rejects TS7 main). Upgrade the toolchain from the workspace root with the current global `vp migrate --full`, not one package at a time.
- **Docker image:** release stage has no curl or pnpm (HEALTHCHECK uses Node `fetch`). Dependabot ignores Node majors until Node 26 LTS (2026-10-28); then bump the image and every workflow's `runtime: node@` together.
- **Release:** a release commit bumps `compose.prod.yaml`'s `${LOGWELL_VERSION:-vX.Y.Z}` with `package.json` `version` (CI lint enforces; release.yml `resolve` fails a tag whose commit's package.json/compose pin name another version — a prerelease may sit on the plain `vX.Y.Z` bump). `workflow_dispatch` builds the commit an existing tag points to; dispatch from the tag ref ("Use workflow from: <tag>") or the Sigstore attestation is skipped with a warning. `:latest` and the latest GitHub Release move only for the highest stable `vX.Y.Z`; `vX.Y.Z-suffix` tags publish as prereleases.
- **Vulnerabilities (`osv-scanner.toml`, no suppressions):** fix via `overrides` in `pnpm-workspace.yaml` first (e.g. `source-map-js ^1.2.2`); only then a per-advisory `[[IgnoredVulns]]` with `ignoreUntil` — package-wide ignores stay out.
- **Postgres 18-alpine** everywhere (PG19 beta — don't bump). `db:push` dev-only; prod/CI `db:migrate`. `db:generate` needs TTY; if it replays old migrations (meta snapshots cover 0000–0005, 0011–0014), hand-write SQL.
- Env (`.env.example` documents every variable and default): `NODE_ENV` allow-list — only `development`/`test` relax rules; unset, `staging`, anything else = production. `DATABASE_URL` (must start `postgres`, required), `BETTER_AUTH_SECRET` (≥32, required unless dev/test, published placeholders rejected), `ORIGIN` (public URL; read by the app, not adapter-node 6 — CSRF guard + better-auth trusted origin + HSTS when https; unset → sign-out fails on plain HTTP, production warns at startup), `DB_STATEMENT_TIMEOUT_MS` (30000) / `DB_IDLE_IN_TRANSACTION_TIMEOUT_MS` (60000) (whole ms, 0 = server default, max 3600000, invalid fails startup; sent as startup params — PgBouncer transaction mode needs `ignore_startup_parameters`; also bounds CSV export + retention batches), `LOG_CLEANUP_BATCH_PAUSE_MS` (100), `SSE_MAX_CONNECTIONS` (200), `RATE_LIMIT_LOGIN_ACCOUNT_RPM` (30), `INGEST_MAX_FUTURE_SKEW_MS` (300000), `RATE_LIMIT_*_RPM`, `SSE_*`, `LOG_*`, `BODY_SIZE_LIMIT` (image: 1M; over-limit ingest → 413 `payload_too_large`), `SHUTDOWN_TIMEOUT` (image: 8s, under Docker's 10s stop grace). `IDLE_TIMEOUT` is adapter-node's socket-activation shutdown, not a connection timeout, `INCIDENT_AUTO_RESOLVE_MINUTES=30`. Behind proxy set `ADDRESS_HEADER` + `XFF_DEPTH` or IP limiting sees socket IP.
- Never commit/push/rebase unless asked; never `reset --hard`, `clean -fd`, print secrets.

## Testing & QA

Tier by **filename suffix** (Playwright excluded from Vitest). Import from `vite-plus/test`, not `vitest`.

| Tier        | Glob                                                                  | DB            | Command                     |
| ----------- | --------------------------------------------------------------------- | ------------- | --------------------------- |
| Unit        | `src/**/*.unit.test.ts`                                               | mocked        | `pnpm run test:unit`        |
| Component   | `src/**/*.component.test.ts` (jsdom + Testing Library)                | none          | `pnpm run test:component`   |
| Integration | `tests/integration/**/*.integration.test.ts` + `scripts/**/*.test.ts` | PGlite        | `pnpm run test:integration` |
| E2E         | `tests/e2e/**`                                                        | real Postgres | `pnpm run test:e2e`         |

- **Integration:** fresh PGlite per test via schema reflection (not `drizzle/*.sql`); new column types may need `test-db.ts` type map / `tableOrder` or table silently skipped. Seed via `tests/fixtures/db.ts` (`seedProject`, `seedLog`, `seedProjectWithApiKey` — plaintext once); add same-origin `Origin`; `clearApiKeyCache()` in `beforeEach`.- **Conventions before refactor:** timeseries/incident-detail/timeline tests spy on `db.select` and throw on full-row pulls — aggregate in SQL. `hooks.server.unit.test.ts` drives the real `handle` (session population, `/v1` + `/api/health` fast paths, login + `/v1` rate limits, signup kill-switch, CSRF).
- **E2E:** CI preview `:4173` (`workers:1 retries:2`), local dev `:5173` (default workers, no retries), `extraHTTPHeaders` Origin, admin `admin/adminpass`, `RATE_LIMIT_LOGIN_RPM=10000`, login specs wrap in `expect(…).toPass({timeout:45000})`. Helpers: `helpers/otlp.ts`, `helpers/log-selectors.ts`. Chromium+firefox local, chromium-only CI.
- Pre-commit: Vite+ dispatcher runs `vp staged && vp check && pnpm run knip` (plus SDK check when SDK files are staged). Run `pnpm run check` for Svelte/TS and nearest test tier for touched code. Coverage signal-only.
